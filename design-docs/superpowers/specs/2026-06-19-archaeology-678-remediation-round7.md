## Confirmed findings

### T1 — #7 CLASS INCOMPLETE: extent-DERIVING transforms not pinned under facet (S2)
`fix_transform_extents_for_facet` (`render/prepare.rs:1684-1771`) pins only extent-**carrying** transforms (those with a serde `extent` field: Kde/Bin/Violin/Kde2D/Bin2D/DensityData). Three extent-**deriving** transforms compute their grid extent from per-partition data and have NO `extent` field, so they drift per panel under facet:
- **`Hex`** (`transform/hex.rs:180-207`) — auto `bin_size = (xmax-xmin)/30` from per-panel xmin/xmax → different data-unit cell size per panel → incomparable pixel cell sizes (reproduced: narrow vs wide panel hex-cell width ratio **6.13×**).
- **`Raster`** (`transform/raster.rs:208-228` + `render/marks/image.rs:266-283`) — per-partition grid extent stretched across each panel's scale → each panel's image spans ~97% of its panel even for disjoint data.
- **`DataBin`** (`transform/data_bin.rs:53-64`) — per-partition bin boundaries → non-comparable binned positions/labels under facet (S1, niche: explicit transform API, rarely faceted, but same class).

The round-5 enumeration "all extent-carrying transforms" should have read "all extent-**deriving** transforms".

### T2 — finding-C INCOMPLETE: stub SIGNATURE drift (existence-only parity test missed it) (WARN→fix)

### T3 — conditional/crossfilter packed-ordering bug (S2, interactive-only, pre-existing) (USER: fix on branch)
`crates/ferrum-wasm/src/conditional.rs` (`resolve_conditionals_with_packed` ~176-244; `apply_crossfilter_to_panel` ~96-135). The WASM flat instance array is packed-FIRST (`load_scene_with_packed` unpacks all packed instances, then appends scene-walk non-packed), but the conditional walk indexes non-packed batches by a running `circle_offset`/`rect_offset` that counts only packed instances seen before it in SCENE order — not all packed instances. When a non-packed batch precedes a same-kind packed (≥1000-mark) batch in scene order (e.g. a LayerChart of a 50-pt scatter + a 1500-pt scatter), a selection/crossfilter dims the WRONG instances. The one regression test uses packed-FIRST ordering, so it coincidentally passes. **Fix:** index instances by the loader's actual basis — record/use per-(panel,batch) `instance_start` for non-packed batches too (draw commands already carry it), instead of the scene-order running offset.

### T4 — FOUNDATIONAL: faceted RAW-field positional scale resolves per-panel, not shared (S2, pre-existing) (USER: fix on branch)
For a faceted RAW continuous (or categorical) field with `ResolveMode::Shared` (the documented default, `ferrum-spec.md:709/822`), marks are per-panel-scaled while the axis shows the global domain → marks and axis labels disagree (verified: panel A x=10 lands on the shared '100' tick). Root cause: `ResolveMode::Shared` is consumed only for axis layout, never domain resolution. `numeric_domain_union` (`render/scale_resolve/domain.rs:381-419`) deliberately excludes `FINAL_OUTPUT_KEY` (the global all-panels concat) when `primary_has` is true (`:412`, doc comment `:367-368`), so a faceted raw field's domain = per-panel min/max only. The ordinal/band arm in `build_axis_scale` (`positional.rs:95-107`) has the SAME class (a panel omitting categories present only in other panels). Confirmed by round-6 scene-pipeline audit + an independent repro.

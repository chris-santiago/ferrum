## Confirmed findings

### A — CRITICAL: `_merge_packed_data` tooltip-table misparse (drops/blanks panels)
`src/ferrum/composition.py:2776-2779`. The tooltip-section skip assumes a single u32 total-byte-length prefix. The real Rust format (`pack_instances.rs::pack_tooltips`, reader `crates/ferrum-wasm/src/scene_load.rs::unpack_binary_instances`) has NO overall length prefix: `[num_fields:u32]` + `num_fields`×`[len:u32][name]` + `count×num_fields`×`[len:u32][value]`. It reads `num_fields` as the table byte-length, advances ~6 bytes, desyncs, and either (1) drops every batch after the first (2nd+ panels' marks vanish + garbage tooltips on panel 0) or (2) blanks the whole chart via a downstream `scene_load.rs:735` out-of-bounds slice panic. Auto-tooltips are on by default (`_auto_tooltips=True`), so HAS_TOOLTIPS is set on nearly every packed batch → ANY interactive composite (concat/grid/joint/clustermap/repeat; titled single-panel via `_render_single_with_figure_chrome`) whose child has >1000 circles/rects is corrupted. Reproduced end-to-end. Pre-existing (commit `8583f7e`, 2026-05-18). **Fix:** scan the tooltip string table field-by-field exactly as `scene_load.rs` does, advancing `batch_end` to the true end.

### B — HIGH: packed instances never get the per-panel X/Y composition offset
`src/ferrum/composition.py` `_merge_child_scenes*` (`:2134,2217,2289,2378`) call `_merge_packed_data(..., y_offset=header_h)` and rewrite only the header `panel_idx` + the figure-title `header_h` Y-shift. They never apply the per-child concatenation `dx`/`dy` (panel grid placement) to the packed instance X/Y. So a child's scene-graph nodes/plot_area/axes ARE offset by dx/dy (via `_merge_scene_panels`/`_offset_node`) but its ≥1000 packed GPU marks are NOT — packed marks render at the leftmost/top-left child's coordinates, mispositioned out of their panel; the R-tree hit-test is built from the same un-offset instances so selection lands wrong too. There is `_offset_packed_batch_y` but no x-offset, and the panel dx/dy is not threaded to packed at all. **Fix:** thread the per-panel (dx, dy) into the packed path and offset both X and Y of each instance by the panel's composition translation (in addition to the header_h band). Unify with T3's Y-offset (one packed-instance translate(dx, dy+header_h)).

### C — BUG: `_core.pyi` stub drift (typed callers crash / invisible kwargs)
`src/ferrum/_core.pyi`. `Violin.__init__` stub declares `extent=` which the REAL Rust constructor rejects (TypeError) — a typed caller passing `Violin(extent=...)` type-checks then crashes; stub also missing `bw_adjust`. `Kde`/`Smooth`/`Robust`/`Kde2D` stubs missing real kwargs live callers pass (`bw_adjust`/`shared_extent`/`kernel`/`groupby`/`inject_metrics`/`x_range`…). ~19 registered classes (DensityData, RegressionData, LoessData, the Data* transforms, …) + ~15 functions (render_interactive, rasterize_svg, figure_title_nodes, the diagnostic kernels) undeclared; `render_svg`/`render_png` stubs missing `chart_config`. **Fix:** correct the stub to match the real bindings (at minimum remove the wrong `Violin extent=` and add the missing kwargs/classes/functions the effort touched; full stub regen if tractable).
